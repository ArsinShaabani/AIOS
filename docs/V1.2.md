# AIOS v1.2 — Models, Skills & Chat power features

## Provider & model controls (no more truncated answers)
Every provider now accepts per-model limits, editable in **Models**:

| Field | Meaning |
|---|---|
| `max_tokens` | Output cap (provider/model default). Raise it for long answers. |
| `context_window` | Total context budget used to trim history. |
| `temperature`, `top_p` | Sampling defaults for this provider. |
| `reasoning_effort` | `low` / `medium` / `high` (OpenAI-compatible reasoning models). |

Chats can override these per message (⚙ in the composer): max tokens, temperature,
context window and reasoning effort. The effective prompt budget is
`context_window − max_tokens − 512`, so long sessions no longer get silently cut at
12k characters; the hard safety ceiling is 200k characters per message.

## Fetch models after adding a key
**Models → Add/Edit provider → “Fetch models from provider”** calls
`POST /api/v1/admin/providers/discover` with the draft config (or the stored key).
Supported discovery endpoints:

- OpenAI-compatible: `GET {base_url}/models` (Groq, Mistral, DeepSeek, OpenRouter, LM Studio, vLLM, llama.cpp…)
- Ollama: `GET {base_url}/api/tags`
- Anthropic: `GET {base_url}/v1/models`
- Gemini: `GET {base_url}/models?key=…`

Add `?save=true` (the UI does not, so you can review first) to persist the list.

### Free / no-cost options
| Preset | Key required | Notes |
|---|---|---|
| Ollama (local) | no | Best for 1 CPU / 1 GB; runs on the same host |
| LM Studio, llama.cpp, vLLM | no | Any OpenAI-compatible local server |
| Pollinations | no | `https://text.pollinations.ai/openai` — rate-limited, no SLA |
| Groq | yes (free tier) | Very fast Llama/Mixtral inference |
| Google Gemini | yes (free tier) | `gemini-2.0-flash` etc. |
| OpenRouter | yes (free tier) | Models suffixed `:free` |
| Mistral / Cerebras / Hugging Face | yes (free quota) | OpenAI-compatible endpoints |

The in-app catalog contains the exact base URLs and model names.

## Skills & agents
**Skills & Agents** ships 12 installable templates (researcher, staff engineer,
data analyst, home manager, IoT operator, robotics copilot, planner, editor,
tutor, localizer, SRE, security reviewer). Installing one creates an editable
agent with its own prompt, tool allow-list and routing keywords.

- `GET /api/v1/agents/catalog`
- `POST /api/v1/agents/install {"id":"coder"}`

## Chat upgrades
- **Attachments**: drag & drop, paste or 📎 up to 6 files (5 MB each). Text,
  code, CSV, JSON and Markdown are extracted and appended to the prompt; images
  are referenced (a vision-capable provider is required for pixel-level input).
- **Code → WebView**: every fenced block gets **Preview**. HTML runs as-is;
  CSS/JS/SVG/Markdown are wrapped in a sandboxed `iframe` (`allow-scripts`,
  no same-origin) so generated UI can be inspected safely.
- **Character picker**: 👤 opens a card gallery with tone, humour and length
  traits, plus a shortcut to create a new character.
- **Advanced options**: temp/max-tokens/context/effort per conversation.
- Stop, regenerate, copy and tool cards remain available.

## Appearance
Settings gained code font size and chat width (stored per browser), alongside
theme, accent, density, font size and reduced-motion.

## API additions
```
POST /api/v1/admin/providers/discover       # fetch models (draft or stored key)
GET  /api/v1/agents/catalog                 # skills library
POST /api/v1/agents/install                 # install a skill
```
`POST /api/v1/chat` now accepts `options` and `attachments` and allows up to
200k characters. The default request body limit was raised to 8 MB.
